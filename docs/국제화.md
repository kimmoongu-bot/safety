# 국제화 — 폰 언어에 맞춰 내보내기 위한 준비

목표는 **폰 설정 언어에 맞춰 앱이 그 언어로 뜨는 것**이다. 한국어로 시작해 영어·일본어를
먼저 붙이고, 그다음 언어를 늘린다.

이 문서는 두 가지를 적는다.
1. 되돌리기 어려운 결정과 그 근거
2. 언어를 하나 추가할 때 실제로 해야 하는 일

---

## 1. 인터넷 없이 한다

번역문은 앱 안에 같이 넣어서 내보낸다. 실행 중에 어디서도 받아오지 않는다.

명세 1장이 "MVP 목표는 인터넷 권한조차 요구하지 않는 것"이라고 못박았고, `app.json` 은
`INTERNET` 과 `ACCESS_NETWORK_STATE` 를 막아 두었다. 번역을 서버에서 받아오는 순간 그
약속이 깨진다. **번역 때문에 인터넷 권한을 열지 않는다.**

폰 언어를 읽는 것은 `expo-localization` 이 한다. OS 설정을 읽을 뿐이고 권한도 통신도
필요 없다.

## 2. 되돌리기 어려운 것 — 이미 정해진 대로 간다

화면 문장은 언제든 고칠 수 있다. 하지만 **이미 사용자 폰에 저장된 것**은 못 고친다.
그래서 데이터에 언어가 섞여 들어가지 않게 하는 것이 국제화의 핵심이다. 아래 넷은
지금 이미 그렇게 돼 있고, **앞으로도 바꾸지 않는다.**

### 2.1 백업 파일 안에 사람 언어를 넣지 않는다

`.jamgim` 파일에 들어가는 것은 `jamgim-backup`, 숫자, base64, 암호문뿐이다.
한글도 영문 문장도 없다.

- 한국어 폰에서 만든 백업을 영어 폰에서 되살릴 수 있다.
- 폰 언어를 바꿔도 예전 백업이 그대로 열린다.

헤더는 통째로 AAD 로 묶여 있다. 여기에 언어에 따라 달라지는 값을 하나라도 넣으면
**다른 언어에서 인증 태그가 안 맞아 파일이 열리지 않는다.** 절대 넣지 않는다.

파일 *이름*(`잠김_백업_삭제금지_20260831.jamgim`)만 사람이 읽는 문장이다. 이름은
프로그램이 파싱하지 않으므로 언어별로 바꿔도 안전하다. 확장자 `.jamgim` 은 ASCII 로 고정.

### 2.2 복구 코드는 영문·숫자로 고정한다

한국 사용자가 만든 복구 코드를 다른 나라에 있는 가족이 받아 적을 수 있어야 한다.
한글이나 각국 문자를 섞으면 그 순간 그 코드는 그 나라에서만 쓸 수 있는 것이 된다.
전화로 불러 주기, 종이에 옮겨 적기, 다른 기기에서 입력하기가 전부 막힌다.

혼동 문자(0/O, 1/I 등)를 이미 뺀 문자 집합을 쓴다. 이 결정은 국제화 이전에 내렸지만
국제화가 그 근거를 하나 더 보탠다.

### 2.3 저장 형식에 언어를 넣지 않는다

레코드의 평문 필드(id, createdAt, updatedAt, favorite, schemaVersion)는 전부 언어와
무관하다. 사용자가 적은 서비스명·아이디·메모는 어느 문자든 들어올 수 있고 전부
암호문으로 들어가므로 문제되지 않는다.

### 2.4 좌우 뒤집힘(RTL)에 안전하다

아랍어·히브리어는 화면 전체가 좌우로 뒤집힌다. 코드에 "왼쪽"이 박혀 있으면 그 부분만
안 뒤집혀서 화면이 깨진다.

확인해 보니 좌우를 지정한 곳은 네 군데뿐이고 **전부 양쪽이 같은 값**이다(알림 상자의
좌우 여백, 가림 뷰의 전체 덮기). 뒤집혀도 결과가 같다. 글자 정렬도 전부 가운데다.

**앞으로 지킬 것**: 한쪽만 다른 값을 줘야 할 때는 `left`/`right` 대신 `start`/`end` 를 쓴다.

## 3. 지금 구조에서 고쳐야 하는 것

### 3.1 조사 조립을 없앤다 — 이게 제일 크다

지금은 문장을 조각으로 **조립**한다.

```ts
`${label}을(를) 복사했습니다`   // josa.ts 가 받침을 보고 을/를을 고른다
```

한국어에서는 맞지만, 이 방식은 다른 언어로 못 넘어간다. 어순이 다르기 때문이다.

| 언어 | 실제 문장 | 조각 조립으로 되나 |
|---|---|---|
| 한국어 | {label}을 복사했습니다 | 됨 |
| 일본어 | {label}をコピーしました | 조사가 다름 |
| 영어 | Copied {label} | **어순이 반대** |
| 독일어 | {label} wurde kopiert | 동사가 뒤로 감 |

**문장을 언어마다 통째로 갖는다.** 자리 표시자(`{label}`)만 남기고 나머지는 그 언어의
완성된 문장이다. `josa.ts` 는 한국어 문장표 안으로 들어가고, 화면 코드에서는 사라진다.

원칙: **화면 코드에서 문자열을 `+` 로 잇지 않는다.**

### 3.2 개수 표현

"3개를 되살렸습니다"는 한국어라서 1개든 3개든 문장이 같다. 다른 언어는 다르다.

| 언어 | 갈래 |
|---|---|
| 한국어·일본어 | 1갈래 |
| 영어·독일어 | 2갈래 (1 item / 3 items) |
| 러시아어 | 3갈래 |
| 아랍어 | 6갈래 |

`Intl.PluralRules` 가 어느 갈래인지 알려 준다. 문장표는 갈래별로 갖는다.

### 3.3 시간·숫자 표현

"1분", "60초", "90일" 같은 것은 `Intl` 에 맡긴다. 직접 "분"을 붙이지 않는다.

### 3.4 오류 문장을 코드로만 만든다

`src/core` 안에 사람이 읽을 문장은 없다. 코드만 던지고 말은 `ko.ts` 가 정한다.

코드는 두 층이다. `code` 는 무슨 종류의 실패인가(`WRONG_PIN`), `detail` 은 같은 종류
안에서 **해야 할 일이 다른** 경우다. 예를 들어 `VAULT_LOCKED` 안에는 '이 기기에 지문이
준비 안 됨'과 '지문 정보가 바뀜'이 있는데, 둘은 사용자가 할 일이 다르다.

문장 열쇠는 코드에서 바로 만든다 — `error.WRONG_PIN`. 그래서 코드를 하나 더 만들고
문장을 안 적으면 **타입 검사에서 걸린다.** 일부러 한 줄을 지워서 실제로 잡히는 것과,
빠진 열쇠 이름을 짚어 주는 것까지 확인했다.

## 4. 화면이 깨지는 것을 미리 잡는다

지금 "스크롤 없이 한 화면에 들어온다"는 것을 실기기에서 확인했다. **그건 한국어라서
들어온 것이다.** 같은 뜻이 다른 언어에서는 길어진다.

| 언어 | 한국어 대비 길이 |
|---|---|
| 일본어 | 비슷 |
| 영어 | 1.2~1.5배 |
| 독일어·핀란드어 | 1.3~1.8배 |
| 러시아어 | 1.3~1.6배 |

명세 3장이 요구하는 **본문 17sp·터치 48dp·글꼴 200% 확대**를 지키면서 1.8배 긴 문장을
담아야 한다. 여기가 가장 많이 깨질 곳이다.

**대책**: 문장을 일부러 길게 만든 가짜 언어(`xx-LONG`)를 하나 만들어 둔다. 모든 문장을
1.8배로 늘려 놓은 것이다. 이 언어로 화면을 훑으면 번역을 기다리지 않고도 깨지는 곳을
찾을 수 있다. 자동 검사에도 넣는다.

## 5. 언어를 고르는 규칙

```
1) 사용자가 설정에서 직접 고른 언어가 있으면 그것
2) 없으면 폰 설정 언어에 맞는 것
3) 그것도 없으면 영어
```

**기본값을 영어로 하는 이유**: 태국어 폰에서 앱을 열었는데 한국어가 뜨면 한 글자도 못
읽는다. 영어면 최소한 버튼은 알아본다.

**설정에 언어 항목을 두는 이유**: 폰은 영어인데 앱은 모국어로 보고 싶은 사람이 있다.
해외 교포·이주민에게 흔한 경우다.

고른 언어는 설정에 저장한다. 금고 안(암호문)에는 넣지 않는다. 언어는 비밀이 아니고,
**잠긴 상태에서도 화면 문장이 필요하기 때문이다.** 금고를 열어야 언어를 알 수 있으면
잠금 화면을 무슨 언어로 그릴지 알 수 없게 된다.

## 5-1. 지금 어디까지 됐나 (2026-09-02)

**화면 문장을 다 옮겼다.** `src/app` 안에 화면에 보이는 한국어가 한 줄도 남지 않았다
(주석 제외). 문장 197개가 `src/app/i18n/ko.ts` 한 파일에 모였다.

| | |
|---|---|
| `i18n/types.ts` | 문장 목록의 뼈대, `{name}` 채우기, 개수 갈래 |
| `i18n/pickLocale.ts` | 언어 고르는 규칙 |
| `i18n/pseudo.ts` | 가짜 언어 `xx-LONG` |
| `i18n/categories.ts` | 갈래 코드 ↔ 보이는 말 |
| `i18n/ko.ts` | **번역자에게 이 파일만 주면 된다** |
| `i18n/index.ts` | 화면에서 쓰는 `useT()` |
| `core/prefs.ts` · `state/prefsStore.ts` | 고른 언어·밝기를 금고 밖에 보관하는 곳 |

옮기면서 **말을 만들던 모듈 넷**을 고쳤다. 이 모듈들은 이제 말을 갖지 않는다.

- `platform/biometrics.ts` — "지문·얼굴" 을 만들었다 → 종류만 돌려준다
- `platform/screenGuard.ts` — 실패 문장을 만들었다 → 무엇이 잘못됐는지만 돌려준다
- `platform/reminders.ts` · `platform/backupFile.ts` — 알림·창 제목을 부르는 쪽이 넘긴다

**갈래는 코드로 저장한다.** 예전에는 "은행" 같은 한국어가 금고에 그대로 들어갔다.
그러면 일본어 사용자가 자기 금고에서 한국어 갈래를 보게 된다. 이제 `bank` 를 저장하고
화면에서 번역한다. 코드를 쓰기 전에 저장된 옛 항목의 한국어는 **그대로 보여 준다** —
옛 항목이 갑자기 빈칸이 되면 안 된다.

**날짜도 나라 방식으로 쓴다.** `2026년 9월 2일` 을 직접 조립하던 것을 `Intl` 에 맡겼다.

### 검사가 지키는 것 (`tests/i18n.test.ts`)

- 화면이 부르는 열쇠가 문장 목록에 실제로 있는지 — 오타를 잡는다
- 옮긴 파일에 화면용 한국어가 **다시 들어오지 않는지**
- 자리 표시자에 값이 들어가는지 (20가지)
- 조사가 앞말에 따라 바뀌는지 (`지문으로` / `얼굴로`)

### 남은 것

  기기 키로 감싼 파일). 어두운 모드 설정과 같은 자리를 쓴다.
  화면에는 **고를 것이 둘 이상일 때만** 나온다. 지금은 한국어뿐이라 안 보인다.
  `AVAILABLE` 에 언어를 한 줄 더하면 그때 나타난다.
- **영어·일본어 번역.** `ko.ts` 를 복사해 옮기면 된다.

## 6. 언어 하나를 추가할 때 하는 일

1. `src/app/i18n/ko.ts` 를 복사해 `<언어>.ts` 를 만들고 번역한다
   (번역자에게 이 파일 하나만 넘기면 된다. 코드를 볼 필요가 없다)
2. `src/app/i18n/index.ts` 에 등록한다
3. `xx-LONG` 으로 이미 잡아 둔 자리 말고 실제로 깨지는 곳이 있는지 화면을 훑는다
4. 스토어 등록 정보를 그 언어로 쓴다 (아래 7장)
5. 개인정보처리방침을 그 언어로 옮긴다

## 7. 스토어 등록 정보 — 언어마다 같은 선을 지킨다

명세 8장은 **"절대 안전", "해킹 불가" 같은 표현을 쓰지 않는다**고 못박았다.
이 규칙은 **번역문에도 그대로 적용된다.** 번역하면서 슬쩍 세지는 일이 흔하다.

| 쓰지 않는다 | 대신 |
|---|---|
| absolutely safe / unhackable / military-grade | encrypted on your device / AES-256-GCM |
| 絶対安全 / ハッキング不可能 | 端末内で暗号化 |

`docs/위협모델.md` 의 표가 모든 언어의 기준이다. **그 표보다 강한 말은 어떤 언어로도
쓰지 않는다.** 번역자에게 위협 모델 표를 같이 넘긴다.

또 하나: **"복구 불가"를 부드럽게 옮기지 않는다.** PIN 과 복구 코드와 백업을 모두 잃으면
되살릴 수 없다는 것은 이 앱의 설계다. 번역에서 "복구가 어려울 수 있습니다" 정도로
누그러뜨리면 사용자가 복구 코드를 안 적어 둔다. 원문만큼 단호하게 옮긴다.

## 8. 아직 안 정한 것

- **글꼴**: 지금은 OS 기본 글꼴을 쓴다. 한중일 글자가 섞이면 OS 가 알아서 고르는데,
  기기에 따라 어색해 보일 수 있다. 실기기에서 봐야 안다.
- **앱 이름**: "잠김"을 각 언어로 옮길지, 로마자 "Jamgim"으로 통일할지.
  스토어 검색과 브랜드에 영향이 있어 따로 정해야 한다.
- **아랍어·히브리어**: 구조상 갈 수 있다는 것만 확인했다. 실제로 넣어 보진 않았다.
