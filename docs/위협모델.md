# 위협 모델 — 지키는 것과 못 지키는 것

이 표를 문서와 스토어 설명의 기준으로 삼는다. 여기 적힌 것보다 더 강한 표현은 쓰지 않는다.

| 위협 | 결과 | 무엇이 막아 주나 |
|---|---|---|
| 잠긴 폰 분실·도난 | 방어 | 저장된 것이 전부 암호문. 열쇠는 PIN 유도 키 + OS 키 저장소의 기기 키 두 겹 |
| 백업 파일만 유출 | 방어 | 백업 전용 비밀번호로 따로 감쌌고, 헤더까지 인증에 묶여 있다 |
| 비루팅 기기에서 앱 데이터 추출 | 방어 | 기기 키가 OS 키 저장소 밖으로 나오지 않는다. 파일만으로는 열 수 없다 |
| 어깨너머 훔쳐보기 | 부분 방어 | 비밀번호 기본 숨김, 표시 후 15초 자동 숨김, 화면 캡처 차단 |
| 루팅·탈옥 기기 | 탐지·경고만, 완전 방어 불가 | 키 저장소를 우회할 수 있다 |
| 키로거·악성앱 감염 | **방어 불가** | 입력 자체를 가로채면 앱이 할 수 있는 일이 없다 |
| 해제된 상태에서 타인 조작 | 부분 방어 | 자동 잠금 기본 1분, 백그라운드 진입 즉시 잠금 |
| 사용자가 PIN·복구 코드 분실 | 복구 불가 — 설계상 정상 | 백업 파일 + 백업 비밀번호가 마지막 수단 |

## 설계에서 일부러 받아들인 것

- **PIN 을 잊고 복구 코드도 잃고 백업도 없으면 복구할 수 없다.** 이 문장을 최초 설정과
  설정 화면 양쪽에 그대로 노출한다. 뒷문을 두면 그 문으로 남도 들어온다.
- **생체정보를 새로 등록하면 지문·얼굴로 여는 길만 막힌다.** 생체 슬롯과 기기 키를 따로 둔
  이유가 이것이다. PIN·복구 코드 경로는 그대로 살아 있다.
- **검색을 위해 서비스명을 평문으로 두지 않았다.** 대신 금고를 연 뒤 전체를 메모리에서 거른다.
  수백 건 규모까지를 전제로 한 선택이고, `schemaVersion` 이 나중의 방식 전환을 가능하게 한다.
