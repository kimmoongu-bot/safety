# 위협 모델 — 지키는 것과 못 지키는 것

이 표를 문서와 스토어 설명의 기준으로 삼는다. 여기 적힌 것보다 더 강한 표현은 쓰지 않는다.

| 위협 | 결과 | 무엇이 막아 주나 |
|---|---|---|
| 잠긴 폰 분실·도난 | 방어 | 저장된 것이 전부 암호문. 열쇠는 PIN 유도 키 + OS 키 저장소의 기기 키 두 겹 |
| 백업 파일만 유출 | 방어 | 백업 전용 비밀번호로 따로 감쌌고, 헤더까지 인증에 묶여 있다 |
| 비루팅 기기에서 앱 데이터 추출 | 방어 | 기기 키가 OS 키 저장소 밖으로 나오지 않는다. 파일만으로는 열 수 없다 |
| 어깨너머 훔쳐보기 | 부분 방어 | 비밀번호 기본 숨김, 표시 후 15초 자동 숨김, 화면 캡처 차단 |
| 루팅·탈옥 기기 | 탐지·경고만, 완전 방어 불가 | 키 저장소를 우회할 수 있다 |
| 키로거·악성앱 감염 | **방어 불가** | 입력 자체를 가로채면 앱이 할 수 있는 일이 없다 |
| 해제된 상태에서 타인 조작 | 부분 방어 | 자동 잠금 기본 1분, 백그라운드 진입 즉시 잠금 |
| 사용자가 PIN·복구 코드 분실 | 복구 불가 — 설계상 정상 | 백업 파일 + 백업 비밀번호가 마지막 수단 |

## 설계에서 일부러 받아들인 것

- **PIN 을 잊고 복구 코드도 잃고 백업도 없으면 복구할 수 없다.** 이 문장을 최초 설정과
  설정 화면 양쪽에 그대로 노출한다. 뒷문을 두면 그 문으로 남도 들어온다.
- **생체정보를 새로 등록하면 지문·얼굴로 여는 길만 막힌다.** 생체 슬롯과 기기 키를 따로 둔
  이유가 이것이다. PIN·복구 코드 경로는 그대로 살아 있다.
- **파일 고르기·보내기·지문 확인 창이 떠 있는 2분 동안은 백그라운드로 나가도 잠그지 않는다.**
  명세 5.5 는 "백그라운드로 가는 즉시 파기"라고 못박았지만, 그대로 두면 백업 파일을
  고르는 순간 금고가 잠겨 되살리기를 끝낼 수 없다. 그래서 **사용자가 방금 그 창을 눌렀을
  때에 한해** 2분 한도로 예외를 둔다. 그 사이에도 화면은 가림 뷰로 덮이고, 2분을 넘기면
  평소대로 잠근다. 시스템 창을 거치지 않는 일반적인 앱 전환은 예외 없이 즉시 잠근다.
- **'inactive' 상태에서는 잠그지 않고 화면만 가린다.** iOS 는 지문·얼굴 확인 창이나 알림
  센터가 잠깐 덮을 때도 'inactive' 를 보내는데, 여기서 잠그면 생체인증으로 여는 것 자체가
  불가능해진다. 실제로 앱을 떠나는 'background' 에서만 파기한다.
- **복사한 비밀번호는 60초 뒤에 지운다. 그 전에는 안 지운다.**
  한때 "앱을 벗어나면 즉시" 지우게 만들었더니, 카카오톡으로 넘어가는 순간 비워져서
  붙여넣기가 아예 안 됐다. 복사하는 이유가 다른 앱에 붙여넣기 위해서다.
  명세가 정한 60초를 지킨다.
- **클립보드에 대해 앱이 못 하는 두 가지가 있다. 이건 방어 못 하는 쪽에 넣는다.**
  - 삼성 등 일부 폰은 **클립보드 기록**을 따로 보관한다. 앱이 현재 클립보드를
    비워도 그 목록에는 남는다. 앱에서 지울 방법이 없다.
  - 안드로이드 13+ 의 "민감 데이터" 표시(붙여넣기 미리보기를 가리는 것)는
    지금 쓰는 라이브러리(expo-clipboard)가 내주지 않는다. 넣으려면 네이티브
    코드를 따로 붙여야 한다. 아직 안 했다.
  - 앱이 완전히 종료되면 60초 타이머도 사라진다. 다음에 앱을 켤 때 지운다.
- **검색을 위해 서비스명을 평문으로 두지 않았다.** 대신 금고를 연 뒤 전체를 메모리에서 거른다.
  수백 건 규모까지를 전제로 한 선택이고, `schemaVersion` 이 나중의 방식 전환을 가능하게 한다.
