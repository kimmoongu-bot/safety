# 완료 기준 (DoD, 디오디) 현재 상태

`npm test` 로 확인되는 것과, 실기기에서 사람이 직접 봐야 하는 것을 나눠 적는다.
**"코드를 썼다"는 통과가 아니다.** 확인 방법이 없는 항목은 미완으로 둔다.

## 보안 코어 — 통과

- [x] UI(유아이) 없이 단위 테스트만으로 암·복호화, 래핑/언랩, PIN(핀) 검증, 복구 코드 언랩이 모두 통과
      → `tests/crypto.test.ts`, `tests/vault.test.ts`
- [x] 같은 nonce(논스)가 두 번 생성되지 않음을 테스트로 확인
      → `tests/crypto.test.ts` "nonce 는 두 번 생성되지 않는다" (5만 개 생성, 전부 다름)
      → 난수원이 고장 나면 조용히 넘어가지 않고 예외를 던지는 것까지 확인

## MVP(엠브이피)

- [ ] **실기기에서 잠금 → 등록 → 검색 → 보기 → 복사 → 수정 → 자동 잠금 전 구간 동작**
      → 화면 8개와 연결은 모두 구현했고 Metro(메트로) 번들까지 확인했다. 실기기 확인은 남았다.
- [x] 앱 데이터 파일을 직접 열었을 때 평문 비밀번호가 0건
      → `tests/records.test.ts` "저장 파일에는 평문이 0건이다". 저장소에 실제로 들어가는
        직렬화 결과를 그대로 훑어서 서비스명·아이디·비밀번호·메모·PIN 을 모두 찾는다.
        SQLite(에스큐엘라이트) 어댑터도 같은 `VaultRecord` 를 그대로 넣으므로 기기에서도 같은 값이 저장된다.
- [ ] 앱 전환 화면·최근 앱 목록에 금고 내용이 보이지 않음
      → 안드로이드는 `expo-screen-capture` 로 FLAG_SECURE(플래그 시큐어), iOS(아이오에스)는 `PrivacyShield` 가름 뷰.
        **실기기 확인 필요.**
- [ ] 클립보드가 설정 시간 후 실제로 비워짐
      → `copySensitive` 가 예약 삭제하고, 잠길 때 즉시 비운다. **실기기 확인 필요.**
- [x] PIN 연속 실패 대기 시간이 앱 재시작 후에도 유지됨
      → `tests/lockout.test.ts` "실패 횟수는 앱을 다시 켜도 남아 있다"
      → 시계를 되돌리는 우회, 기록 파일만 지우는 우회도 함께 막았는지 확인한다.

## 백업/복구 — 통과

- [x] 기기 초기화(앱 삭제 후 재설치) → 백업 파일 + 백업 비밀번호로 복구 성공
      → `tests/backup.test.ts`. 저장소·키 저장소를 모두 새로 만든 뒤 되살린다.
- [x] 잘못된 백업 비밀번호로는 복구 실패하며 앱이 죽지 않음
      → 틀린 비밀번호·빈 값·손댄 파일·형식이 다른 파일 모두 사용자 문장으로 끝난다.
- [x] PIN 을 잊은 상태에서 복구 코드만으로 금고 열기 성공
      → `tests/vault.test.ts` "PIN 을 잊어도 복구 코드로 열린다"

## 착수 전 확인 사항 중 남은 것 (명세 2장)

명세는 아래 라이브러리의 최신 버전과 API(에이피아이)를 **직접 확인하고 고정하라**고 했다.
버전은 `package.json` 에 고정했지만, 실제 기기에서 함수 시그니처까지 확인한 것은 아니다.
개발 빌드를 처음 올릴 때 이것부터 본다.

| 라이브러리 | 쓰는 곳 | 확인할 것 |
|---|---|---|
| `react-native-quick-crypto` | AES-256-GCM(에이이에스-256-지씨엠), PBKDF2(피비케이디에프투) | `createCipheriv` 의 `authTagLength` 옵션, `scrypt` 존재 여부 |
| `react-native-argon2` | Argon2id(아르곤투아이디) | 인자 형식(문자열 vs 바이트)과 `rawHash` 반환 형식 |
| `expo-secure-store` | 기기 키 / 생체 키 | `requireAuthentication` 동작, 생체 재등록 시 무효화 여부 |
| `expo-sqlite` | 레코드 저장 | SQLCipher(에스큐엘사이퍼) 지원 여부. 안 되면 지금처럼 필드 암호문 + 일반 SQLite 로 간다 |

`src/app/platform/deviceCryptoProvider.ts` 는 Argon2id 나 scrypt(에스크립트)를 못 쓰면
자동으로 다음 후보로 내려가게 되어 있다. 다만 **PBKDF2 60만 회 미만으로는
어떤 경우에도 내려가지 않는다** (`assertParamsAcceptable` 이 막는다).
