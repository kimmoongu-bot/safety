# 완료 기준 (DoD) 현재 상태

`npm test` 로 확인되는 것과, 실기기에서 사람이 직접 봐야 하는 것을 나눠 적는다.
**"코드를 썼다"는 통과가 아니다.** 확인 방법이 없는 항목은 미완으로 둔다.

## 보안 코어 — 통과

- [x] UI 없이 단위 테스트만으로 암·복호화, 래핑/언랩, PIN 검증, 복구 코드 언랩이 모두 통과
      → `tests/crypto.test.ts`, `tests/vault.test.ts`
- [x] 같은 nonce 가 두 번 생성되지 않음을 테스트로 확인
      → `tests/crypto.test.ts` "nonce 는 두 번 생성되지 않는다" (5만 개 생성, 전부 다름)
      → 난수원이 고장 나면 조용히 넘어가지 않고 예외를 던지는 것까지 확인

## MVP

- [ ] **실기기에서 잠금 → 등록 → 검색 → 보기 → 복사 → 수정 → 자동 잠금 전 구간 동작**
      → 안드로이드 실기기에서 **금고 만들기 · 잠금 해제 · 등록 · 검색까지 확인했다.**
        복사 · 수정 · 자동 잠금은 아직 확인하지 않았다.

      실기기에서만 드러난 것들 (모두 고쳐서 올림):
      - 최초 설정 중 자동 잠금이 걸려 복구 코드가 눈앞에서 사라졌다.
        가만히 있어야 하는 화면에서 가만히 있었다고 잠근 셈이다.
        → 설정 화면에서는 잠그지 않는다 (`src/app/lockPolicy.ts`, 테스트 있음)
      - 잠금을 푼 뒤의 오류를 아무도 받지 않는 자리에 두어서, 금고는 열렸는데
        화면이 잠금에 멈추고 아무 문구도 뜨지 않았다. PIN 도 지문도 똑같이 먹통.
        → 금고가 열리면 화면부터 옮기고, 그 뒤 실패는 문구로 알린다
      - 항목 하나가 손상되면 금고 전체가 안 열렸다 → 열리는 것은 다 보여 주고
        "N개 항목을 열지 못했습니다"로 알린다
      - 알림 상자가 화면 아래에서 버튼·내비게이션 바에 가려 잘렸다 → 위쪽으로
      - 잠금 화면이 길어 실패 안내가 밀려났다 → 로고를 빼고 한 화면에 담음
      - "지문·얼굴으로도" 조사 오류, 복구 코드 줄바꿈, 스위치 글자(끔→꺼짐)

      여기서 돌려 볼 수 있는 것(테스트·타입·번들)은 다 통과했는데도 이만큼 나왔다.
      실기기 확인을 건너뛰면 안 되는 이유다.
- [x] 앱 데이터 파일을 직접 열었을 때 평문 비밀번호가 0건
      → `tests/records.test.ts` "저장 파일에는 평문이 0건이다". 저장소에 실제로 들어가는
        직렬화 결과를 그대로 훑어서 서비스명·아이디·비밀번호·메모·PIN 을 모두 찾는다.
        SQLite 어댑터도 같은 `VaultRecord` 를 그대로 넣으므로 기기에서도 같은 값이 저장된다.
- [ ] 앱 전환 화면·최근 앱 목록에 금고 내용이 보이지 않음
      → 안드로이드는 `expo-screen-capture` 로 FLAG_SECURE, iOS 는 `PrivacyShield` 가름 뷰.
        **실기기 확인 필요.**
- [ ] 클립보드가 설정 시간 후 실제로 비워짐
      → `copySensitive` 가 예약 삭제하고, 잠길 때 즉시 비운다. **실기기 확인 필요.**
- [x] PIN 연속 실패 대기 시간이 앱 재시작 후에도 유지됨
      → `tests/lockout.test.ts` "실패 횟수는 앱을 다시 켜도 남아 있다"
      → 시계를 되돌리는 우회, 기록 파일만 지우는 우회도 함께 막았는지 확인한다.

## 착수 전 확인 사항 (명세 2장) — 확인함

명세는 라이브러리의 **최신 버전과 API 를 직접 확인하고 고정하라**고 했다.
처음에는 이것을 건너뛰고 기억에 있는 버전(SDK 51)을 썼는데, 실기기 빌드를
돌리는 단계에서 그 대가를 치렀다. 지금은 설치된 파일의 타입 정의를 직접 열어
확인했다.

| 라이브러리 | 버전 | 확인한 것 |
|---|---|---|
| `expo` | 57.0.18 (당시 최신) | SDK 51 → 57. `expo-file-system` 이 `File`/`Directory`/`Paths` 로 완전히 바뀌어 저장소 어댑터를 다시 썼다 |
| `react-native` | 0.86.3 | SDK 57 이 요구하는 버전 |
| `react-native-quick-crypto` | 1.1.7 | `createCipheriv`(`authTagLength` 옵션 있음), `createDecipheriv`, `pbkdf2`, `scrypt`, `randomBytes`, **`argon2`** 모두 있음. 입력은 `Buffer` 로 넘겨야 한다 |
| `expo-secure-store` | 57.0.2 | `requireAuthentication` 옵션 유지 |
| `expo-sqlite` | 57.0.2 | 지금은 필드 단위 암호문 + 일반 SQLite. SQLCipher 가 필요하면 그때 바꾼다 |

### Argon2 라이브러리를 없앴다

`react-native-quick-crypto` 1.x 에 Argon2 가 들어 있다. 따로 쓰던
`react-native-argon2` 를 뺐다. 네이티브 모듈이 하나 줄면 빌드에서 깨질 곳도,
공격 표면도 그만큼 준다. AES-GCM · Argon2id · scrypt · PBKDF2 를 모두 한
라이브러리에서 가져온다.

기기에서 Argon2 를 쓸 수 있는지는 앱을 켤 때 아주 작은 값으로 한 번 확인하고,
안 되면 scrypt → PBKDF2 로 내려간다. **어느 경우에도 PBKDF2 60만 회 아래로는
내려가지 않는다** (`assertParamsAcceptable` 이 막는다).

### nitro 버전은 정확히 맞춰야 한다

`react-native-quick-crypto` 는 `react-native-nitro-modules` 위에 올라가 있고,
빌드 때 C++ 코드를 직접 컴파일한다. 이 생성 코드는 **만들어질 당시의 nitro 버전**
헤더를 그대로 참조한다. 버전이 어긋나면 이렇게 깨진다.

    error: NitroModules cannot be found! Are you sure you installed NitroModules properly?
    error: use of undeclared identifier 'PropNameIDCache'

quick-crypto 1.1.7 은 nitrogen 0.33.2 로 만들어졌다(그 패키지의 devDependencies 에
적혀 있다). 그런데 peerDependencies 는 `>=0.31.2` 라고만 해 두어서, 범위를 느슨하게
잡으면 npm 이 0.31.x 를 고른다. 0.31.x 에는 `PropNameIDCache.hpp` 가 아예 없다.

그래서 **정확한 버전으로 고정한다**: `"react-native-nitro-modules": "0.33.2"`.
quick-crypto 를 올릴 때는 그 패키지의 `devDependencies.nitrogen` 을 보고 이 값도
같이 맞춰야 한다. 범위(`^`, `~`)로 두지 않는다.
