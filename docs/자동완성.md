# 자동 완성 — 설계 (아직 만들기 전)

로그인 칸을 눌렀을 때 **잠김이 아이디와 비밀번호를 대신 채워 주는 것.**

지금은 앱을 열고, 항목을 찾고, 복사하고, 다른 앱으로 건너가서 붙여넣어야 한다.
비밀번호 관리 앱을 쓰는 가장 큰 이유가 이것인데 우리에게 없다.

이 문서는 **만들기 전에 갈림길을 정리한 것**이다. 코드는 아직 없다.

---

## 1. 안드로이드가 요구하는 것

안드로이드에는 자동 완성 얼개(Autofill Framework)가 있다. 우리가 할 일은 셋이다.

1. `AutofillService` 를 상속한 클래스 하나 (코틀린)
2. 매니페스트에 그 서비스를 등록 — `BIND_AUTOFILL_SERVICE` 권한이 붙어야 한다.
   이 권한은 **시스템만 우리 서비스에 연결할 수 있게** 막는 것이라, 우리가 무언가를
   더 얻는 권한이 아니다. 인터넷 권한은 여전히 필요 없다 (명세 1장).
3. 사용자가 **폰 설정에서 잠김을 자동 완성 앱으로 골라야 한다.** 우리가 몰래 켤 수
   없고, 켜서도 안 된다.

`android.permission.BIND_AUTOFILL_SERVICE` 는 우리 앱이 요청하는 권한이 아니라
서비스에 다는 표시다. 스토어의 권한 목록에 늘어나는 것이 없다 — 확인 필요.

## 2. 갈림길 — 자동 완성 서비스가 금고를 직접 여느냐

여기가 이 일의 전부다.

### 갈래 A — 코틀린이 직접 연다

자동 완성 서비스 안에서 SQLite 를 읽고, 키 저장소에서 기기 키를 꺼내고,
AES-GCM 과 Argon2 를 **코틀린으로 다시 구현해** 복호화한다.

**안 된다.** 이유가 셋이다.

- **열쇠 계층이 두 벌이 된다.** 명세 5장을 자바스크립트로 한 번, 코틀린으로 한 번
  구현하게 된다. 한쪽만 고치면 조용히 어긋나고, 어긋난 것을 알아챌 방법이 없다.
  지금까지 이 앱에서 난 사고는 전부 "같은 것이 두 군데 있었다" 였다.
- **DEK 가 우리가 통제 못 하는 프로세스에 들어간다.** 자동 완성 서비스의 수명은
  안드로이드가 정한다. 명세 5.5 의 자동 잠금(뒤로 가면 즉시 잠금)을 지킬 수 없다.
- **실패 대기(5.4)를 우회하는 길이 생긴다.** 잠금 화면을 거치지 않고 금고를 여는
  두 번째 문이 생기는 것이다.

### 갈래 B — 앱을 띄워서 연다 ← 이쪽으로 간다

안드로이드 자동 완성에는 **인증(authentication)** 이라는 길이 있다. 서비스가
"내용은 잠겨 있다. 사용자가 확인해야 한다" 고 답할 수 있다.

    로그인 칸을 누른다
      → 안드로이드가 우리 서비스에 묻는다
      → 서비스는 "잠김" 한 줄만 내놓는다 (내용 없음)
      → 사용자가 그 줄을 누른다
      → **우리 앱 화면이 뜬다** — 평소 그 잠금 화면이다
      → PIN 이나 지문으로 연다
      → 목록에서 고른다
      → 고른 값을 안드로이드에 돌려준다 → 칸이 채워진다

**코틀린 쪽은 암호를 하나도 모른다.** 하는 일이 둘뿐이다.

- 화면 구조를 읽어 어느 칸이 아이디이고 어느 칸이 비밀번호인지 알아낸다
- 사용자가 고른 결과를 안드로이드에 돌려준다

금고는 늘 우리가 아는 그 한 길로만 열린다. 자동 잠금도, 실패 대기도, 화면 캡처
막기도 전부 그대로 적용된다. **문이 하나 더 생기는 것이 아니라, 같은 문으로
들어오는 손님이 하나 느는 것이다.**

## 3. 갈래 B 에서도 남는 위험

자동 완성은 **비밀번호를 다른 앱에 건네는 일**이다. 성격상 위험이 남는다.

**① 어느 앱에 주는지 사용자가 알아야 한다.**
안드로이드가 요청한 앱의 꾸러미 이름(package)을 알려 준다. 채우기 화면에 그것을
**크게** 보여 준다. 가짜 앱이 남의 비밀번호를 달라고 하는 것을 막는 것은
결국 사람 눈이다.

**② 자동으로 채우지 않는다.**
사람이 목록에서 골라야만 채운다. 이름이 비슷하다고 알아서 넣지 않는다.
중장년층 대상이라 한 번 더 묻는 쪽이 맞다.

**③ 브라우저 안의 웹사이트는 꾸러미 이름이 브라우저다.**
크롬 안에서 은행에 로그인하면 꾸러미는 크롬이다. 그래서 웹 주소(webDomain)도
같이 읽어 보여 준다. 이것 없이 꾸러미만 보면 아무 사이트나 같아 보인다.

**④ 화면 캡처 막기가 채우기 화면에도 걸려야 한다.**
우리 화면이니까 걸린다. 확인은 실기기에서 해야 한다.

## 4. 단계

한 번에 다 만들지 않는다. 각 단계마다 실기기에서 확인한다.

1. **서비스 뼈대** — 매니페스트 등록, 설정 화면에 "자동 완성 켜는 법" 안내.
   내용 없이 "잠김" 한 줄만 내놓는다. 폰 설정에 우리가 뜨는지부터 본다.
2. **화면 구조 읽기** — 어느 칸이 아이디이고 어느 칸이 비밀번호인지 찾는다.
   `autofillHints` 가 있으면 그것을, 없으면 칸 이름과 종류를 본다.
   **이 판단만 순수 함수로 떼어 내면 노드에서 검사할 수 있다.** 나머지는 실기기다.
3. **채우기 화면** — 요청한 앱·주소를 보여 주고, 잠금을 풀고, 목록에서 고른다.
4. **돌려주기** — 고른 값을 안드로이드에 넘긴다.
5. **저장 제안** (나중) — 새 비밀번호를 만들면 "잠김에 담을까요?" 하고 묻는다.

## 5. 정해야 할 것

- **가장 낮은 안드로이드 판.** 자동 완성은 안드로이드 8.0(API 26)부터다. 지금
  우리는 API 24 부터 돈다. 24·25 를 버릴지, 아니면 그 판에서는 이 기능만 없는
  채로 둘지 정해야 한다. 뒤쪽이 맞아 보이지만 손이 조금 더 간다.
- **채우기 화면을 지금 잠금 화면으로 쓸지, 따로 만들지.** 지금 것을 쓰면 "어느 앱이
  달라고 하는지" 를 보여 줄 자리가 없다. 따로 만드는 쪽이 맞아 보인다.

## 6. 확인할 수 없는 것

이 기능은 **거의 전부 실기기에서만 확인된다.** 노드 테스트로 잡을 수 있는 것은
2단계의 칸 찾기 판단 정도다. 그래서 단계를 잘게 나눈다 — 한 번에 만들어 놓고
"안 되는데요" 를 들으면 어디서부터 틀렸는지 알 수 없다.
