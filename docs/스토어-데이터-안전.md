# 스토어 등록 자료

## Google Play "데이터 안전" 섹션 답변

| 항목 | 답변 |
|---|---|
| 앱이 데이터를 수집하나요? | **아니요** |
| 앱이 데이터를 공유하나요? | **아니요** |
| 전송 중 데이터가 암호화되나요? | 해당 없음 (전송하지 않음) |
| 사용자가 데이터 삭제를 요청할 수 있나요? | 해당 없음 (수집하지 않음). 앱 안에서 직접 삭제 가능 |
| 앱이 인터넷 권한을 쓰나요? | 아니요 |

기기 안에 저장되는 값은 "수집"에 해당하지 않는다. 다만 설명란에 저장 방식을 적어 둔다.

## 스토어 설명 문구 규칙

**쓰지 않는 말**: "절대 안전", "해킹 불가", "군용 등급", "100% 보안", "완벽한 보호".

지킬 수 없는 약속이고, 심사에서도 문제가 된다. 대신 할 수 있는 말만 쓴다.

**쓸 수 있는 말**

- 저장할 때 내용을 암호로 잠급니다 (AES-256-GCM).
- 서버가 없습니다. 내용이 기기 밖으로 나가지 않습니다.
- 인터넷 권한을 요청하지 않습니다.
- 폰을 잃어버려도 저장된 내용은 암호문으로 남습니다.
- 숫자(PIN)·복구 코드·백업 파일이 모두 없으면 되살릴 수 없습니다. (이 문장을 반드시 넣는다)

## 개인정보 처리방침 웹 주소

스토어는 방침을 볼 수 있는 **웹 주소**를 요구한다. 문서만으로는 안 된다.

웹 한 장은 `site/index.html` 이고, **`docs/개인정보처리방침.md` 에서 만들어 낸다.**

```
node --experimental-strip-types tools/site/build-privacy.ts
```

손으로 따로 쓰지 않는다. 사본이 둘이 되면 언젠가 한쪽만 고치고, 그러면 앱에 적힌
말과 웹에 적힌 말이 달라진다. 심사에서도 걸리고, 무엇보다 읽는 사람을 속이는
셈이 된다. `tests/site.test.ts` 가 둘이 어긋나면 잡는다.

원본 맨 위의 인용 덩이는 우리끼리 하는 말이라 웹에 안 나간다. 그것도 검사가 본다.

### 올려 둔 곳 (2026-09-12)

```
https://kimmoongu-bot.github.io/jamgim-site/
```

**`kimmoongu-bot/jamgim-site`** — 공개 저장소이고 깃허브 페이지로 나간다.
이 작업 저장소(`safety`)는 비공개라 페이지를 못 내보낸다. 그래서 따로 두었다.

플레이 콘솔의 **개인정보처리방침 URL** 칸에 위 주소를 넣는다.

### 방침을 고치면 두 곳을 갱신한다

1. `docs/개인정보처리방침.md` 를 고친다 (그리고 앱 안 `privacy.*` 문장도)
2. `node --experimental-strip-types tools/site/build-privacy.ts` 로 다시 만든다
3. **만들어진 `site/index.html` 을 `jamgim-site` 저장소에 올린다**

3번을 잊기 쉽다. 여기 검사가 닿지 않는 곳이다 — 남의 저장소라 우리 검사가 못
본다. 고치는 김에 같이 하는 수밖에 없다.

> **주소가 오래 살아 있어야 한다.** 스토어에 박히는 주소이고, 죽으면 심사에서
> 걸린다. 저장소를 지우거나 비공개로 바꾸면 그 순간 죽는다.
