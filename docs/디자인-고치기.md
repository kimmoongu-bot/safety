# 디자인 고치기 — 준비

## 1. 먼저 할 일: 빠른 고리 만들기

**지금 방식으로는 디자인을 못 고친다.** 색 하나 바꾸고 15분 빌드를 기다릴 수는
없다. 보고 바꾸고 다시 보는 일을 수십 번 해야 하는 것이 디자인이다.

다행히 이미 `expo-dev-client` 가 들어 있다. 딱 한 번만 빌드하면, 그 뒤로는
화면 코드를 고치는 즉시 폰에 **몇 초 만에** 반영된다.

### 한 번만 (5~15분)

```
cd C:\Users\kim\safety
$env:JAMGIM_DEV_BUILD="1"
npx expo run:android
```

`--variant release` **를 빼는 것**이 핵심이다. 그러면 개발용으로 만들어지고,
피시의 화면 서버에 붙는다.

### 그 뒤로는 (몇 초)

```
cd C:\Users\kim\safety
$env:JAMGIM_DEV_BUILD="1"
npx expo start --dev-client
```

폰에서 `잠김 (개발)` 을 열어 두면, 피시에서 코드를 고치고 저장하는 순간 화면이
바뀐다. 빌드가 없다.

- 폰과 피시가 **같은 와이파이**에 있어야 한다
- 화면이 안 바뀌면 폰을 흔들어 나오는 메뉴에서 `Reload`
- 네이티브(코틀린)를 고치면 이 고리로는 안 된다. 그때만 다시 빌드한다

## 2. 디자인이 사는 곳

고칠 자리는 거의 전부 이 네 파일 안이다.

| 파일 | 무엇 |
| --- | --- |
| `src/app/theme/palette.ts` | **색 한 벌** — 밝은 것과 어두운 것 |
| `src/app/theme/index.ts` | **글자 크기, 여백, 모서리, 터치 크기** |
| `src/app/theme/fonts.ts` | 글꼴 (언어마다 다름) |
| `src/app/components/Basics.tsx` | 단추·입력칸·제목 등 **공통 부품의 생김새** |

화면 하나만 고칠 일이면 `src/app/screens/` 안의 그 파일을 본다. 하지만 **여러
화면이 같이 바뀌어야 하는 것은 거의 언제나 위 네 파일에서 한 번에 바꾸는 것이
맞다.** 화면마다 따로 고치면 곧 서로 어긋난다.

### 색을 바꿀 때

`palette.ts` 에 두 벌이 있다 — `lightColors` 와 `darkColors`. **반드시 둘 다
바꾼다.** 밝은 데서 예쁜 색이 어두운 데서는 안 보이는 일이 흔하다.

### 크기·여백을 바꿀 때

`theme/index.ts` 의 `font`(글자 크기), `space`(여백), `radius`(모서리),
`TOUCH`(터치 크기)를 쓴다. 화면 파일에 숫자를 직접 적지 않는다.

## 3. 건드리면 안 되는 것 — 검사가 막는다

명세 3장에서 온 규칙이고, 사람이 눈으로 지킬 수 없어서 전부 검사로 못박아 두었다.
어기면 `npm run check` 가 어디가 틀렸는지 알려 준다.

| 규칙 | 검사 |
| --- | --- |
| **글자 대비 4.5:1 이상** — 두 벌 모두, 15가지 짝을 전부 잰다 | `tests/palette.test.ts` |
| **굵기를 숫자로 주지 않는다** (`fontWeight: '700'` 금지) | `tests/hygiene.test.ts` |
| **글자 크기를 정하는 곳은 글꼴도 함께 정한다** | `tests/hygiene.test.ts` |
| 두 색 한 벌이 같은 이름을 모두 갖는다 | `tests/palette.test.ts` |
| 일본어 글자가 글꼴에 들어 있다 | `tests/fontCoverage.test.ts` |

**왜 굵기를 숫자로 주면 안 되나.** 굵기는 글꼴 이름으로 고른다
(`font.familyBold`). 거기에 `fontWeight` 를 또 주면 안드로이드가 **이미 굵은
글꼴을 한 번 더** 굵게 그린다. 획이 뭉개진다.

**검사가 못 막는 것 둘.** 이건 사람이 봐야 한다.

- **터치 크기 48dp** — `TOUCH` 상수는 있지만 모든 단추가 그걸 쓰는지는 검사가
  못 센다
- **글꼴 200% 확대에서 안 깨짐** — 폰 설정에서 글씨를 제일 크게 하고 **모든
  화면을 한 번씩** 봐야 한다. 특히 잠금 화면은 스크롤 없이 한 화면에 들어와야
  한다 (실패 횟수와 대기 시간이 위로 밀려 안 보이면 안 된다)

## 4. 고치고 나서

```
npm run check
```

색·글꼴·굵기 규칙을 어겼으면 여기서 걸린다. 통과하면 올린다.

**글꼴 200% 확대 확인은 손으로 한다.** 다 고친 뒤 한 번에 몰아서 본다.

## 5. 색 (2026-10-16 에 바꿈)

**흰 바탕에 검정 줄.** 어두운 화면에서는 그대로 뒤집힌다.

| | 밝은 것 | 어두운 것 |
| --- | --- | --- |
| 바탕 | `#FFFFFF` | `#000000` |
| 카드·입력칸 | `#FFFFFF` (바탕과 같다) | `#000000` |
| 줄 | `#000000` | `#FFFFFF` |
| 본문 글자 | `#000000` | `#FFFFFF` |
| 흐린 글자 | `#4A4A4A` | `#B5B5B5` |
| 기본 단추 | 검정 바탕 + 흰 글자 | **뒤집힘** — 흰 바탕 + 검정 글자 |

**바탕과 카드가 같은 색이다.** 그래서 무엇이 어디까지인지는 전부 줄이 말한다.
칠해서 구분하던 것들(쪽지, 알림, 입력창)을 전부 줄로 바꿨다.

**뜻을 가진 색 둘만 남겼다.**

- `danger` 빨강 — 지우기. 지우는 단추가 다른 단추와 똑같아 보이면 안 된다
- `ok` 초록 — 잘됨 알림

둘 다 **줄과 글자에만** 쓴다. 바탕은 어디서나 흰색이다.

## 6. 무엇을 바꾸고 싶은지 정하기

막연히 "예쁘게" 는 고칠 수가 없다. 아래 중 어디가 걸리는지 짚어 주시면 된다.

- **색** — 크림색이 칙칙하다 / 갈색 강조가 안 어울린다 / 더 밝았으면
- **글자** — 작다 / 크다 / 글꼴이 딱딱하다
- **여백** — 빽빽하다 / 휑하다
- **단추** — 네모가 투박하다 / 색이 심심하다
- **특정 화면** — 목록이 심심하다 / 잠금 화면이 허전하다 / 넣기 화면이 길다

화면 사진에 동그라미를 쳐서 보내 주셔도 좋다. 말보다 빠르다.
