# 내 컴퓨터에서 빌드하기 (윈도우)

지금까지는 EAS(클라우드)에서 빌드했다. 한 번에 15~20분이고, 무료 횟수에 한도가 있다.
2026년 9월에 그 한도를 다 써서 막혔다.

**여기서 하는 빌드는 3~5분이고 횟수 제한이 없다.** 그리고 더 중요한 것 —
**오류가 나면 화면에 파일 이름과 줄 번호가 바로 뜬다.** 클라우드 빌드에서는 그것을
보기 어려워서, 눈 감고 고치다 빌드를 여러 번 태운 적이 있다.

처음 준비에 한두 시간 걸린다. 그 뒤로는 명령 한 줄이다.

---

## 준비물 두 가지

### 1. 자바 (JDK 17)

<https://adoptium.net> 에서 **Temurin 17 (LTS) · Windows · x64 · .msi** 를 받아 설치한다.

설치 중에 **"Set JAVA_HOME variable"** 항목이 나오면 **켠다.** 기본은 꺼져 있다.
이걸 켜면 아래 환경 변수 설정에서 자바 쪽은 안 해도 된다.

> 왜 17 인가: 이 프로젝트는 Gradle 9.3.1 로 빌드하는데, 그것이 자바 17 이상을
> 요구한다. 더 높은 판도 대개 되지만 17 이 가장 확실하다.

### 2. 안드로이드 스튜디오

<https://developer.android.com/studio> 에서 받아 설치한다. 용량이 크다(수 GB).

설치가 끝나고 처음 열면 **설정 마법사**가 돈다. **Standard** 를 고르고 그대로
진행한다. 안드로이드 SDK 를 알아서 받는다.

> 우리가 코드를 안드로이드 스튜디오에서 편집하지는 않는다. **SDK 때문에 까는 것이다.**

## 환경 변수 정하기

윈도우 검색창에 **"환경 변수"** 라고 치면 **"시스템 환경 변수 편집"** 이 나온다.
그것을 열고 **[환경 변수]** 단추를 누른다.

위쪽 **사용자 변수**에서 **[새로 만들기]** 로 이것을 더한다.

| 변수 이름 | 값 |
|---|---|
| `ANDROID_HOME` | `C:\Users\kim\AppData\Local\Android\Sdk` |

`JAVA_HOME` 이 이미 있으면 그대로 두고, 없으면 이것도 더한다.

| 변수 이름 | 값 |
|---|---|
| `JAVA_HOME` | `C:\Program Files\Eclipse Adoptium\jdk-17...` (설치된 폴더 이름 그대로) |

그다음 같은 화면에서 **`Path`** 를 골라 **[편집]** → **[새로 만들기]** 로 두 줄을 더한다.

    %ANDROID_HOME%\platform-tools
    %ANDROID_HOME%\emulator

**확인을 다 누르고, 열려 있던 PowerShell 창을 모두 닫는다.** 환경 변수는 새로 연
창부터 적용된다.

## 제대로 됐는지 확인

PowerShell 을 **새로** 열고 한 줄씩 친다.

```
java -version
```
→ `openjdk version "17...` 이 나와야 한다.

```
adb version
```
→ `Android Debug Bridge version ...` 이 나와야 한다.

```
echo $env:ANDROID_HOME
```
→ SDK 폴더 경로가 나와야 한다.

**셋 중 하나라도 안 나오면 여기서 멈추고 알려 주세요.** 다음으로 가면 엉뚱한 데서
헤맨다.

---

## 폰 준비

1. 폰 **설정 → 휴대전화 정보 → 소프트웨어 정보** 에서 **빌드 번호**를 **일곱 번** 누른다
   → "개발자 모드를 켰습니다" 가 뜬다
2. **설정 → 개발자 옵션 → USB 디버깅**을 켠다
3. 폰을 USB 로 컴퓨터에 꽂는다
4. 폰에 **"USB 디버깅을 허용하시겠습니까?"** 가 뜨면 **허용**

확인:

```
adb devices
```

→ 기기가 한 줄 나오고 옆에 **`device`** 라고 적혀 있어야 한다.
`unauthorized` 면 폰에서 허용을 안 누른 것이다.

## 빌드

```
cd safety
```

```
$env:JAMGIM_DEV_BUILD="1"
```

```
npx expo prebuild --platform android
```

```
npx expo run:android --variant release
```

3~5분 뒤 폰에 저절로 깔리고 실행된다.

### `prebuild` 를 빼먹지 마라

**고친 것이 폰까지 안 가고 헛돈다.** 한 번 그래서 두 번을 헛빌드했다.

`android` 폴더는 깃에 없다. `prebuild` 가 설정과 플러그인을 읽어서 **만들어 내는**
것이다. 특히 `plugins/android/JamgimFillActivity.kt` 는 그때 복사된다.

그런데 `run:android` 는 `android` 폴더가 **이미 있으면 prebuild 를 건너뛴다.**
그래서 `git pull` 로 코드를 받아도, 폴더 안에는 **예전 파일이 그대로 남는다.**
빌드는 예전 파일을 컴파일하고, 아까 고친 오류가 똑같이 다시 난다 — 줄 번호까지
똑같아서 "안 고쳐졌나" 싶어진다. 고쳐졌다. 안 간 것뿐이다.

`prebuild` 는 몇 초면 끝나고 이미 만들어 둔 것을 지우지 않는다. 그냥 늘 같이
돌리는 편이 낫다.

### 왜 `JAMGIM_DEV_BUILD` 를 켜나

이 표시가 있으면 앱 이름이 **`잠김 (개발)`** 이 되고 꾸러미 이름도 달라진다
(`app.config.js`). 그러면 **지금 폰에 깔려 있는 진짜 잠김을 건드리지 않고** 나란히
깔린다. 금고에 넣어 둔 것이 그대로 남는다.

이 표시가 없으면 안드로이드가 '같은 앱' 으로 보는데, 클라우드 빌드와 서명이 달라서
설치가 거부되거나 기존 앱을 지워야 한다. **지우면 금고 내용이 사라진다.**

> 대신 개발용 빌드에는 인터넷 권한이 붙는다. 그 빌드는 폰에 시험용으로만 깔고
> 스토어에 올리지 않는다. `tests/appConfig.test.ts` 가 배포용에 인터넷이 들어가지
> 않는지 지킨다.

### 자동 완성을 시험할 때

`잠김 (개발)` 은 **다른 앱**이라 자동 완성도 따로 잡아 줘야 한다.
폰 설정에서 자동 완성 서비스를 **`잠김 (개발)`** 로 바꾼다.

## 오류가 나면

**화면에 나온 빨간 글자를 그대로 주시면 됩니다.** 파일 이름과 줄 번호가 같이
나옵니다. 그게 이 모든 준비의 진짜 이유다.

자주 나는 것 몇 가지.

**`SDK location not found`**
→ `ANDROID_HOME` 이 안 잡혔다. PowerShell 을 새로 열었는지 확인한다.

**`No connected devices`**
→ `adb devices` 로 폰이 `device` 로 보이는지 본다. USB 케이블이 충전 전용이면
데이터가 안 통한다.

**`Could not determine java version` / 자바 판 이야기**
→ `java -version` 이 17 인지 본다.

**빌드가 아주 오래 걸린다 (첫 번째)**
→ 처음 한 번은 라이브러리를 내려받느라 10분 넘게 걸릴 수 있다. 그다음부터 빠르다.
