# 구글 플레이에 올리기

**이 문서를 쓴 날: 2026-09-01.** 스토어 정책은 자주 바뀐다. 아래 내용은 등록 화면에서
직접 확인하면서 진행한다. 이 문서가 틀렸으면 화면이 맞다.

---

## 0. 먼저 알아 둘 것 — 시간이 제일 오래 걸리는 부분

**개인 개발자 계정으로 처음 앱을 내려면, 바로 공개 출시가 안 되는 것으로 알고 있다.**
구글이 2023년 말부터 새 개인 계정에 요구하는 절차다.

- 비공개 테스트를 먼저 한다
- 테스터 **12명 이상**을 모아 **14일 이상** 연속으로 테스트한다
- 그 뒤에 공개 출시(프로덕션) 권한을 신청한다

**즉 앱이 다 됐어도 최소 2주 이상 걸린다.** 여기부터 계산해야 한다.
사업자 계정은 이 요건이 없는 것으로 알고 있으나, **반드시 등록 화면에서 직접 확인한다.**

테스터 12명은 가족·지인의 구글 계정 이메일이면 된다. 실제로 써 볼수록 좋다.
**절차는 1-1 에 자세히 적었다.**

## 1. 개발자 계정 만들기

https://play.google.com/console 에서 가입한다.
**등록비 미화 25달러, 한 번만 낸다** (연회비 아님).

### 개인이냐 사업자냐

가입할 때 고른다. 나중에 바꾸기 어려우므로 처음에 정한다.

| | 개인 | 사업자(단체) |
|---|---|---|
| 확인 서류 | 신분증 | 사업자등록증 + **D-U-N-S 번호** |
| 준비 기간 | 며칠 | D-U-N-S 발급에 **몇 주** 걸릴 수 있다 |
| 테스터 12명 × 14일 | **필요** | **면제**로 알고 있다 (아래 ⚠️) |
| 스토어에 공개되는 주소 | **집 주소** | 사업장 주소 |

⚠️ **"사업자는 테스터 면제" 는 확인한 사실이 아니다.** 이것 때문에 사업자를 고를
생각이라면 **등록 전에 플레이 콘솔 도움말에서 직접 확인한다.** 판단이 뒤집힐 수 있다.

**주소 공개를 미리 알아 두어야 한다.** 구글은 개발자의 실제 주소를 스토어 목록에
공개한다. 개인으로 등록하면 집 주소가 그대로 노출된다. 비밀번호 금고 앱을 만드는
사람에게는 생각해 볼 문제다.

**돈** — 무료 앱이고 앱 내 결제가 없으면 사업자등록 없이 개인으로 낼 수 있는 것으로
알고 있다. 다만 **수익이 생기면 세무 문제가 따로 생긴다.** 이 부분은 세무서나
전문가에게 확인한다.

**권고**: 무료 앱이고 결제가 없으므로 **개인으로 시작**한다. 사업자등록과 D-U-N-S 를
준비하는 사이에 2주는 그냥 지나간다. 주소 공개가 마음에 걸리면 사업자 쪽이 맞고,
그럼 D-U-N-S 번호부터 신청해야 한다(무료지만 시간이 걸린다).

## 1-1. 비공개 테스트 — 테스터 12명은 어떻게 세는가

**개인 계정이면 이 절차를 먼저 거쳐야 하는 것으로 알고 있다.** 아래는 그 절차의
얼개다. **정책 세부는 자주 바뀌므로 콘솔 화면이 최종 기준이다.**

**1) 비공개 테스트 트랙을 만든다**
콘솔에서 `테스트 → 비공개 테스트` 로 들어가 트랙을 만들고 `.aab` 를 올린다.

**2) 테스터를 이메일로 등록한다**
이메일 목록에 주소를 직접 넣거나, 구글 그룹 주소 하나를 넣는다. 12명이면 이메일
목록이 간단하다.

⚠️ **반드시 구글 계정 이메일이어야 한다.** 네이버·다음 주소는 안 된다. 그 사람이
폰에서 로그인해 쓰는 구글 계정이어야 한다.

**3) 참여 링크를 보낸다**
콘솔이 링크를 준다. 12명에게 보내면 각자 그 링크를 열고 **"테스터가 되기"를 눌러야**
한다. **이메일만 등록해 놓으면 안 되고 본인이 수락해야 사람 수에 들어간다.**

**4) 깔고 그대로 둔다**
수락하면 플레이스토어에서 받을 수 있다. **14일 동안 지우지 말라고** 부탁한다.

**5) 콘솔이 세어 준다**
"며칠째, 몇 명" 이 나온다. 조건이 차면 공개 출시 신청 버튼이 열린다.

### 확실히 모르는 것

- 중간에 한 명이 빠지면 날짜가 처음부터 다시 세어지는지 → **여유 있게 14~15명** 모은다
- 정확한 판정 기준(설치만 하면 되는지, 열어 봐야 하는지)

이 앱은 인터넷을 쓰지 않으므로 **구글이 사용 기록을 볼 수 없다.** 그래서 "수락하고
깔아 둔 상태" 가 기준일 가능성이 높다.

### 제일 중요한 것 — 앱 완성을 기다리지 않는다

지금 상태로도 비공개 테스트를 **시작할 수 있다.** 14일은 그냥 흘러가는 시간이고,
그 사이에 새 빌드를 계속 올릴 수 있다.

```
지금 시작    → 14일 동안 앱 다듬기 → 바로 공개 신청
완성 후 시작 → 앱 다듬기 → 그다음 14일 → 공개 신청
```

**2주 차이가 난다.**

순서:
1. 개발자 계정 등록 (본인 확인 며칠)
2. 12~15명 이메일 모으기 ← **지금 할 수 있다**
3. `production` 빌드 한 번 올려서 비공개 테스트 시작
4. 14일 동안 남은 작업 (글꼴 200% 확대, 화면 사진, 처리방침 주소)
5. 공개 신청

### 아직 없는 것 — 이건 사람이 해야 한다

**연락처 이메일**
스토어에 공개된다. 개인 메일을 쓰기 싫으면 앱 전용으로 하나 만든다.
정하면 두 곳에 넣는다: `docs/개인정보처리방침.md` 44번째 줄, 플레이 콘솔 등록 정보.

**개인정보 처리방침 주소**
구글은 파일이 아니라 **공개된 웹 주소**를 요구한다. `docs/store/privacy.html` 을
어딘가에 올려야 한다. 공짜로 하는 법:

- **깃허브 페이지스(GitHub Pages)** — 이 저장소를 쓰면 된다. 저장소 설정 → Pages →
  브랜치 지정. 주소는 `https://kimmoongu-bot.github.io/safety/store/privacy.html` 꼴이 된다.
  단, **저장소가 공개(public)여야 한다.** 지금 비공개면 공개로 바꾸거나 다른 곳을 쓴다.
- 다른 무료 호스팅도 된다. 주소가 계속 살아 있기만 하면 된다.

**화면 사진 (스크린샷)**
폰에서 직접 찍는다. **최소 2장, 보통 4~8장.** 세로로 찍는다.

찍을 화면 (이 순서를 권한다):
1. 잠금 화면 — 숫자판이 보이는 것
2. 내 금고 — 계정이 몇 개 들어 있는 목록
3. 계정 상세 — 비밀번호가 가려진 상태
4. 설정 — 자동 잠금·화면 찍기 막기가 보이는 것
5. **안드로이드 앱 정보 → 권한 화면** ← 이게 우리의 가장 센 한 장이다.
   권한이 하나도 없는 것을 구글 화면이 직접 보여 준다

⚠️ **사진에 진짜 비밀번호가 찍히지 않게 한다.** 시험용 계정만 넣고 찍는다.
(화면 찍기 막기 때문에 앱 안에서는 캡처가 안 된다. 설정에서 잠깐 끄고 찍은 뒤
다시 켠다.)

## 4. 올릴 파일 만들기

스토어는 `.apk` 가 아니라 **`.aab`** 를 받는다. `production` 프로필이 그것이다.

```powershell
cd C:\Users\kim\safety
git pull origin claude/jamgim-vault-app-z0v7sa
npx eas-cli build --platform android --profile production
```

다 되면 `.aab` 파일을 내려받아 플레이 콘솔에 올린다.

**서명 열쇠**는 EAS 가 만들어 보관한다. 이 열쇠를 잃으면 **같은 앱을 갱신할 수 없다.**
`npx eas-cli credentials` 로 백업을 받아 안전한 곳에 둔다. (금고 복구 코드와 같은 성격이다.)

### 버전 올리기

두 번째부터는 올릴 때마다 숫자를 키워야 한다. 같은 숫자는 거부된다.

| `app.json` | 지금 | 뜻 |
|---|---|---|
| `version` | `0.1.0` | 사람이 보는 버전 |
| `android.versionCode` | `1` | 구글이 보는 번호. **올릴 때마다 +1** |

## 6. 문구를 쓸 때 지킬 선 (명세 8장)

`docs/위협모델.md` 의 표가 모든 문구의 상한선이다. **그 표보다 강한 말은 쓰지 않는다.**

| 쓰지 않는다 | 대신 |
|---|---|
| 절대 안전 · 100% 안전 | 기기 안에서 암호로 잠급니다 |
| 해킹 불가 · 뚫을 수 없는 | 잠긴 폰을 잃어버려도 내용은 암호문입니다 |
| 군사급 · 은행급 | AES-256-GCM |

**"복구 불가" 를 부드럽게 바꾸지 않는다.** PIN·복구 코드·백업을 모두 잃으면 열 수 없다는
것은 이 앱의 설계다. 누그러뜨리면 사용자가 복구 코드를 안 적어 둔다.

**아직 사실이 아닌 것은 쓰지 않는다** — 아이폰 지원, 다국어, 자동 채우기.
자세한 것은 `docs/제품소개.md` 9장.
