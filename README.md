# 잠김 (Jamgim)

개인용 아이디·비밀번호 보관 금고. 서버 없음, 계정 없음, 인터넷 권한 없음.

> 사용자가 직접 넣고 직접 꺼내 보는 개인 금고.
> 보장할 수 있는 최대치는 **"기기를 잃어버려도 저장 내용이 암호문으로 남는다"** 까지다.

기준 문서: 통합 제작 시안서 3차 개선본 / 개발 명세서 v1.0

## 돌려 보기

```bash
npm install

npm test              # 보안 코어 단위 테스트 (네이티브 모듈 없이 node 만으로 돈다)
npm run typecheck     # 앱 전체 타입 검사
npm run typecheck:core # 코어만 (엄격 옵션)

npx expo prebuild     # 네이티브 프로젝트 생성 (보안 설정 플러그인이 여기서 적용된다)
npm run android       # 개발 빌드로 실행 — Expo Go 로는 보안 모듈을 쓸 수 없다
```

## 구조

```
src/
  core/                 화면도, 저장소도, 플랫폼도 모르는 순수 로직
    crypto/             AES-256-GCM 래퍼, KDF 정책, nonce 생성기, 주입 지점
    keys.ts             DEK 생성 / 이중 래핑 / 언랩
    vault.ts            금고 한 개를 다루는 진입점
    lockout.ts          실패 카운터와 대기 시간 (5.4)
    backup.ts           .jamgim 파일 포맷
    ports.ts            바깥 세상에 요구하는 인터페이스
  data/adapters/        SQLite · SecureStore · FileSystem · 메모리(테스트) 구현
  app/                  화면 8개, 상태, 플랫폼 연결
tests/                  코어 단위 테스트
plugins/                안드로이드 보안 설정 (자동 백업 제외 등)
docs/                   위협 모델 · 개인정보 처리방침 · 완료 기준
```

의존 방향은 한 방향이다: `app → data → core`. 코어가 `react-native` 나 `expo` 를 부르면
테스트(`tests/hygiene.test.ts`)가 실패한다.

## 바꾸면 안 되는 것 (명세 5장)

코드를 고치기 전에 이것부터 읽는다. **UI 편의를 위해 아래를 완화하지 않는다.**

1. **DEK 는 무작위 32바이트.** PIN 에서 직접 만들지 않는다.
2. **PIN 해시를 저장하지 않는다.** 언랩을 시도해 인증 태그가 맞으면 맞는 PIN 이다.
3. **OS 키 저장소에 DEK 원본을 넣지 않는다.** 넣는 것은 감싸는 키뿐이다.
4. **nonce 를 재사용하지 않는다.** 레코드마다 새로 만든다.
5. **실패 카운터는 앱 재시작으로 초기화되지 않는다.**
6. **payload · DEK · PIN · 복구 코드를 로그에 남기지 않는다.**
7. **평문 JSON 을 파일이나 AsyncStorage 에 저장하지 않는다.** 어떤 임시 구현에서도.

6번과 7번은 테스트가 소스를 직접 훑어서 확인한다.

## 하지 않는 것 (MVP 제외)

자동 로그인/Autofill, 비밀번호 변경 자동 감지, 클라우드 동기화, 광고·분석 SDK·크래시 리포트.

못 만들어서가 아니라 **공격 표면을 늘리지 않기 위해서**다. 이 원칙을 코드 리뷰 기준으로 삼는다.
